# 训练与推理全链路

这份说明把本仓库已经跑通的路径串成一条：文本如何变成监督信号，权重如何更新，checkpoint 如何变成续写，以及 KV Cache 为什么能加速、在窗口满了之后又为什么必须重建。实现只依赖 NumPy 和 Python 标准库。它能讲清 Decoder-only Transformer 的主计算，不代表 ChatGPT 级能力。

对应代码在 `src/lob_transformer/`。命令行用法、网页操作和语料范围以仓库根目录 [README.md](../README.md) 为准。

## 1. 一条链上的角色

```text
语料 / 配对样例
    → Tokenizer（字符 → ID，词表随数据而定）
    → Embedding 查表
    → Transformer Block × N
          Pre-Norm → Causal Attention（Q/K 上 RoPE）→ 残差
          Pre-Norm → MLP（升维 ×4、ReLU、降维）→ 残差
    → 最终 LayerNorm → LM Head → Logits

训练：对目标位置做交叉熵 → 手写反向 → 裁剪 → SGD 或 Adam → 保存 NPZ
推理：贪心取 argmax → 新字符追加进上下文 → 再前向
       可选 KV Cache：提示词一次算完 K/V，之后只处理新字符
```

训练前向和推理前向结构相同，但训练走 `training.py` 里带闭包的 tape，推理走 `TinyGPT.forward` / `_forward_cached`。两边不共用同一套前向函数，权重是同一套。

LM Head 与 Embedding 形状互为转置，训练时独立更新，不共享存储。

## 2. 文件如何对应这条链

| 环节 | 文件 |
| --- | --- |
| 字符词表 | `tokenizer.py` |
| 查表 | `embedding.py` |
| 旋转位置 | `rope.py` |
| 因果多头注意力、KV Cache | `attention.py` |
| LayerNorm / MLP / Block | `normalization.py` `mlp.py` `block.py` |
| 前向、贪心生成 | `model.py` |
| 交叉熵、反向、SGD、语料训练 | `training.py` `data.py` |
| 答案部分损失、Adam、时间任务 | `time_task.py` |
| 权重 + 词表 | `checkpoint.py` |
| 计时与开关对比 | `inference.py` |
| HTTP 与网页 | `server.py` `workbench.py` `static/` |
| 入口 | `cli.py` |

默认模型：2 层、64 维、4 头（时间任务上下文 32；普通 CLI 默认可改）。注意力头维必须为偶数，因为 RoPE 按二维旋转。

## 3. 训练：三种入口，一种损失形状

所有训练都是「用当前位置预测下一个字符」的交叉熵。`loss_and_gradients` 对 `logits[answer_start:]` 求平均损失；普通文本 `answer_start=0`，时间任务只对 `=` 之后的五个答案字符计损。

### 3.1 单序列拟合（`--text`）

文本整段编码，`ids[:-1]` 预测 `ids[1:]`。每步对同一条序列前向、反向、全局梯度裁剪（阈值 1）、SGD。没有验证集，`--save` 存最后一步。用来确认反向传播能把损失压下去，不代表泛化。

```bash
uv run lob-transformer train --text "你好世界你好世界你好世界" --steps 200 --save model.npz
```

### 3.2 语料窗口（`--file` / 网页「普通文本续写」）

整个 UTF-8 文件建词表，再按位置切分：前 90% 训练、末尾 10% 验证（可调）。每步从训练侧合法起点有放回采样 `batch-size` 个长度为 `context-length+1` 的窗口，窗口内错开一位形成输入与目标。每个窗口单独反传，梯度取平均后再裁剪、更新。这是梯度累积，不是向量化大矩阵。

第 0 步、每 10 步和最后一步用两侧固定窗口估 `train_loss` / `val_loss`，训练结束恢复验证损失最低的权重。验证集用于选模型，不是独立测试集。

```bash
uv run lob-transformer train --file data/example.txt --context-length 32 --batch-size 4 --steps 200 --save corpus.npz
```

### 3.3 中文时间转换（配对 + Adam）

固定语法：`中文时间=HH:MM`。按「小时:分钟」分组，80% / 10% / 10% 划分，同一时间的别名不会跨集合。词表只来自训练集。小批量 16，只对答案五字符计损，Adam（β1=0.9，β2=0.999，lr=0.001）加梯度裁剪。每 100 步看验证准确率，保存最高权重；验证准确率达到 99% 时提前结束。测试集只在选定权重后评估一次。

示例产物在 `data/time-task/`（V2 纠错集在 `data/time-task-v2/`）。网页可导入 JSONL、停止任务、看失败案例并启用模型。

```bash
uv run lob-transformer train-time --directory data/time-task
uv run lob-transformer convert-time --text "下午三点半"
```

### 3.4 反向里必须对上的几件事

- Softmax / 交叉熵用 log-sum-exp，避免溢出。
- Attention 的 RoPE 反向：转置旋转等于在负位置再转一次。
- Embedding 用 `np.add.at` 按 token ID 累加梯度，重复字符会叠在同一行。
- 非有限梯度会直接报错，提示降低学习率。
- Checkpoint 是压缩 NPZ + JSON 元数据，不用 pickle；含权重、配置和词表，不含优化器状态、KV Cache 或训练步数。

## 4. 推理：无缓存路径

```text
prompt → encode → 取末尾 context_length 个 ID
       → Embedding → Block × N → LN → LM Head
       → argmax(logits[-1]) → 追加 → 重复
```

`generate` 默认 `use_cache=False`：每步对当前窗口整段再算一遍 Attention。窗口语义是滑动的：序列超过 `context_length` 时丢掉最旧字符，剩下的位置从 0 重新编号。CLI `generate` 走这条路径；网页默认开启缓存，可用开关关掉。

提示词必须非空，字符必须在 checkpoint 词表里。未知字符是 tokenizer 的 `<unk>`（ID 0）；加载后的生成若遇到词表外字符会报错，而不是静默当成 `<unk>` 继续写。

## 5. KV Cache：省掉已经算过的 K/V

开启后，一次生成请求内部持有每层的 `(K, V)`：

1. **Prefill**：对整段提示词（或重建后的滑动窗口）算一遍，得到全部位置的旋转后 K 和未旋转 V。
2. **Decode**：之后每步只送进最新 1 个 token。RoPE 使用 `offset … offset+len-1`，与无缓存时「整段从 0 编号」在窗口未满时等价。
3. **块内因果**：prefill 若一次送入多个新 token，仍用「不能看未来」的掩码，避免块内泄漏。

缓存不写入 checkpoint，不跨 HTTP 请求、不跨模型切换。网页 `/generate`、`/convert-time` 默认 `use_cache=true`；`/benchmark` 在同一提示词和长度下，两种路径各预热一次，再交替测三次取中位数。

窗口未满时，缓存路径应与全量前向数值接近；贪心输出已按多层分段 logits、随机生成和时间模型核对过。浮点顺序不同，在两个 logit 几乎并列时仍可能改写 argmax。

### 为什么窗口满了不能只删 cache 开头

丢掉最旧字符后，剩下的 token 在**第 0 层**的 K/V 可以看成「去掉第一行」。从第 1 层起，每个位置的隐状态已经混合过被删字符的信息，只截 cache 会得到另一套表示，和原实现「截断序列、位置归零、重新前向」不一致。

因此 cache 长度到达 `context_length` 后，每步用当前窗口整段 `_forward_cached` **重建**，位置从 0 起。测速接口的 `window_rebuilds` 就是这类步数。超过窗口的长生成不会一直加速；当前实现不提供无限上下文。

一次本地 2 层 / 64 维 / 上下文 128 的参考：16 字符提示词续写 64 字符，关闭约 24.7 ms，开启约 9.6 ms。短输出、训练抢 CPU、窗口重建都会改变这个比。

## 6. 网页如何把训练和推理接在一起

```bash
./start.sh --checkpoint data/time-task/model.npz
```

工作台把「正在训练的权重」和「当前对外推理的权重」分开。训练在后台线程，刷新页面不中断；产物落到 `web-checkpoints/` 的任务目录。启用模型后，测试页才能续写或做时间转换。

| 页面 | 作用 |
| --- | --- |
| 模型训练 | 时间任务或普通续写；时间任务可生成/导入三份 JSONL |
| 模型管理 | 切换、上传 NPZ、下载模型与语料、看报告、重评测试集 |
| 模型测试 | 续写或时间转换；KV Cache 开关；比较缓存开关速度 |

时间转换在服务端把输入校验为支持的中文时间，补 `=`，固定生成 5 个字符，再用 `HH:MM` 正则检查。格式对不等于语义对：示例报告里 `下午三点` 曾被写成 `13:00`。

## 7. 建议的阅读与复现顺序

1. `tokenize` → `embedding` → `rope` → `attention` → `forward`：看张量形状。
2. `train --text`：看损失下降和训练前后续写对比。
3. `train --file` 或网页普通训练：看验证选模型。
4. `train-time` 或网页时间任务：看部分损失、分集和测试准确率。
5. `serve` / `./start.sh`：打开 KV Cache，用「比较缓存开关速度」对照输出与耗时。

```bash
uv run lob-transformer --help
uv run lob-transformer tokenize --text "你好，Transformer"
uv run lob-transformer forward --text "你好，Transformer"
uv run lob-transformer generate --checkpoint data/time-task/model.npz --prompt "下午三点半=" --tokens 5
```

## 8. 这条链有意没做的事

- BPE / 子词；词表随语料变，扩大词表不会自动获得对话能力。
- 温度采样、top-k、流式输出、OpenAI/Ollama 协议。
- 向量化大 batch、GPU、分布式。
- 跨请求前缀缓存、paged attention、无限上下文。
- 把验证集当独立测试（仅时间任务另有测试集，且只用一次）。

生产推理引擎的位置留给后续的 `lob-inference`。本仓库停在：能训练、能保存、能在本地网页上对比有无 KV Cache 的贪心生成。
